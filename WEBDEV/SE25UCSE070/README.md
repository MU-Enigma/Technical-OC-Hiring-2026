## Setup Instructions

1. Clone the repo and `cd` into /WEBDEV/SE25UCSE070.
2. Install dependencies:
```bash
   npm install
```
3. Make sure MongoDB is running locally on `127.0.0.1:27017`.
4. Start the server:
```bash
   node index.js
```
5. Visit `http://localhost:8080`.

## Database Schema

**Database:** `files` (from the connection string `mongodb://127.0.0.1:27017/files`)
**Collection:** `formats` (Mongoose auto-generates this from the model name `"Format"` in `db/file.js`)

| Field | Type | Notes |
|---|---|---|
| `_id` | ObjectId | Auto-generated by Mongoose|
| `originalFileName` | String | The filename as uploaded by the user |
| `storedFileName` | String | `_id` + original extension — the actual name on disk |
| `fileSize` | Number | Size in bytes |
| `MIMEType` | String | From Multer's detected mimetype |
| `uploadDate` | Date | Defaults to upload time |


After you upload a file, in mongosh - 
```
use files
db.formats.find().pretty()
```

## Architecture Overview

```
Browser → Express routes (index.js) → Multer parses the upload → file gets written to uploads/ → metadata row saved to MongoDB
```

File bytes live on disk in `uploads/` and the metadata lives in MongoDB, in the `formats` collection.

## Design Decisions

- **Filename collisions:** The mongodb auto generated id is used as the file's actual name on the disk to prevent file name collisions.
- **Write ordering:** The file is written to disk *before* the DB row is inserted. If the DB insert then fails, the code deletes the just-written file (`fs.unlinkSync`) so no file is left. If the disk write itself fails, no DB row is ever created.
- **Delete ordering:** The DB row is deleted first, then the file on disk. If the disk delete fails afterward, there will be a harmless leftover file and no DB record pointing to that file
- **Organizing files:** Uploaded files are sharded into `uploads/<year>/<month>/` subfolders based on upload date, so no single directory accumulates a big number of files.
- **Validation:** Uploads are checked against a 20MB size limit enforced by Multer.
- **Batch upload failure handling:** When uploading multiple files at once, each file is validated and saved independently. If one file fails, it's skipped and the rest of the batch still succeeds.

## Assumptions Made

- Max upload size is fixed at 20MB per file
- No file type restriction, any extension is accepted.
- Authentication is not implemented for this
